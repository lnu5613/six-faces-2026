# 骰子PVP v1.3.1 蒙特卡洛模拟器

一个单文件 Python 模拟器，用来回答这类问题：

- 6 人局每个座位的胜率是多少？
- 身份和座次解耦后，哪个身份真的强？
- 2 人局谁克制谁？
- 一局大概打多少回合？终局是“豪赌”还是“最后一舞”？
- 把毒改成叠加、把机器人改成无限复活、把血量随人数缩放，会变好还是变坏？
- Boss 80 HP 到底够不够？

它不追求“完美 AI”，而是用一套明确、可复现的启发式策略，把规则跑十万局，给出胜率、回合数、各骰面的实际伤害/治疗贡献。

## 联机（旧规则，没有跟着更新）

```bash
node server.js
# 打开 http://127.0.0.1:8788/
```

2~6 个浏览器标签 = 2~6 个玩家（最低 2 人）：第一个创建房间，其他人输入 4 位房间码加入，房主开始。30 秒回合计时，超时自动行动；刷新自动重连。零依赖（http + SSE + fetch），服务器权威，客户端只发 intent。

联机冒烟测试：`node test_online.js`（3 个 Node 机器人开房、加入、开始、打完、重开）。

## 快速开始

需要 Python 3.10+（只用了标准库）。

```bash
# 6 人局，身份=骰面（原文规则）
python dice_pvp_sim.py ffa --players 6 --games 5000

# 6 人局，先排座次、再随机发身份（推荐用来测身份强度）
python dice_pvp_sim.py ffa --players 6 --games 5000 --decouple

# 2 人身份克制矩阵（每个格子 1000 局 × 两个先后手）
python dice_pvp_sim.py matrix --games 1000

# 指定两个身份单挑
python dice_pvp_sim.py duel --id1 1 --id2 2 --games 3000 --first 1

# 同身份镜像，测先手优势
python dice_pvp_sim.py mirror --id1 2 --games 3000

# 直接构造“豪赌”15/5 局面：P1 打完 30HP，P2 打完 10HP+闪避2+减伤1
python dice_pvp_sim.py gamble --id1 1 --id2 2 --games 3000

# Boss 模式（--players 是总人数，含 Boss）
python dice_pvp_sim.py boss --players 5 --games 2000

# 只看开局重投率和身份分布
python dice_pvp_sim.py setup --players 6 --games 100000
```

Windows 控制台如果中文乱码，先执行 `chcp 65001`。

## 模式

| mode | 说明 |
|---|---|
| `ffa` | 2～6 人自由混战，按原文规则；可开关终局、解耦、血量缩放等 |
| `setup` | 只跑开局掷骰，统计“需要重投”的概率和身份分布 |
| `matrix` | 6×6 身份单挑矩阵，行胜率对列；每个格子自动跑两个先后手 |
| `duel` | 指定 `--id1` / `--id2` 单挑，可指定 `--first` |
| `mirror` | 双方同身份，统计 seat1 胜率（先手优势） |
| `gamble` | 直接构造 15/5 的豪赌局面，测 P1（30HP）对 P2（10HP+闪避2+减伤1） |
| `boss` | Boss 模式，近似实现；Boss 的面转成全队 AOE |

---

## 常用开关

| 开关 | 作用 |
|---|---|
| `--players N` | 人数，2～6 |
| `--games N` | 局数；默认 ffa/boss=3000，matrix=300 |
| `--seed N` | 随机种子，默认 20261029 |
| `--decouple` | 座次与身份解耦：先排座次，再随机发身份 |
| `--duel-cap N` | 普通玩家的拼点次数，默认 3 |
| `--robot-unlimited-revive` | 让机器人按被动“无限积电复活”（默认按附属“每人一次”） |
| `--gambler-proc P` | 赌徒 +2 的触发率，默认 0.50；原文“3 以上成功”是 0.667 |
| `--poison-stack` | 毒可叠加（默认只刷新） |
| `--hp-scaling` | 初始 HP 随人数缩放（20/23/26/29/32） |
| `--endgame {auto,gamble,lastdance,none}` | 终局策略；`none` 用来测“没有终局重置”的基线 |
| `--ai {focus,threat}` | AI 选目标：压最低血 / 打最高威胁 |
| `--gamble-p2-duels N` | 豪赌 P2 的拼点次数，默认 999（原文“无限制”）；可设 3/1 做对比 |
| `--boss-hp N` | Boss 血量，默认 80 |
| `--max-rounds N` | 防死循环上限，默认 80 |
| `--quiet` | 只打印摘要和身份胜率 |

## 输出怎么读

`ffa` 会打印：

- **avg rounds / median**：平均/中位回合数（一轮 = 所有人各行动一次）。
- **endgame**：本局进入 `lastdance` / `gamble` / `none` 的比例。
- **seat win rates**：每个座位的胜率；`linked` 模式下会同时显示该座位对应身份。
- **identity win rates**：只统计“该身份出现过的局”，所以 5 人局里没出现的身份不会拉低分母。
- **avg dmg**：该身份平均造成的总伤害（含毒、溅射、刃）。
- **face rolls/game / dmg/roll**：每个骰面平均被摇到多少次、每次实际造成多少伤害。
- **heal/game**：每局总治疗量。

`matrix` 的读法：行身份对列身份的胜率，已经平均了两个先后手。例如“猎人 对 机器人 80.2%”表示猎人先手/后手各跑一半后的总胜率。

## 建模假设（重要）

规则里没有写死的地方，模拟器做了显式假设；完整列表见 `dice_pvp_sim.py` 顶部 docstring。最关键的是：

1. **身份=开局骰面，座次=骰面降序**；同点者整组重投。`--decouple` 可改成“先排座次，再随机发身份”。
2. **“回合”按该玩家自己的回合计时**；毒在受害者回合开始时跳。
3. **毒默认不叠加**，重复施放只刷新；`--poison-stack` 可改。
4. **药师的面 1**：可指定目标、可致命；2 人局额外 +1/跳并立刻造成 2 伤害。
5. **赌徒的 +2** 默认按“每次伤害/治疗实例”独立判定，概率取原文的 50%。
6. **骰利刃默认只能在自己回合使用**；“任意时间”在模拟里无法公平建模，这样会略微低估刃的强度。
7. **临死拼点简化为“受到致命伤时触发”**，而不是“预判下回合将死时触发”。
8. **机器人复活默认按附属的“每人最多一次”**；`--robot-unlimited-revive` 可测被动。
9. **2 人局没有终局模式**，因为原文两个终局都要求开局至少 3 人。
10. **Boss 模式是近似实现**：Boss 每个面转成全队 AOE，具体转换见 `boss_turn()`。

## 已知局限

- AI 是启发式：会集火低血、能杀就杀、有霰弹枪就射、有刃就用；它不会做复杂的谈判、结盟、控场。人类局可能更短或更长。
- “任意时间使用骰利刃”没有真正实现成响应窗口；只在自己回合用。
- Boss 模式只是把每个面粗粒度转成 AOE，不等于一张完整 Boss 规则。
- 所有概率都受随机种子影响；报告里的数字来自固定种子的大样本，复现命令见 `results.md`。
